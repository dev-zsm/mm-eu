# The `code` segment

`code` is the main game code that stays in memory: actors support, collision, camera, audio engine, graphics, effects,
scene loading, the menus' shared code. It is file 0049 of the ROM file table (`extracted/0049_00C8A000.bin`), linked
at `0x800A5FE0`, with about 3,580 functions. The `boot` segment must be done the same way first or in parallel.

## Layout of the sources

- `src/code/<module>/func_XXXXXXXX.c`: one C file per function, in a folder per source file of the original game
  (`Camera`, `Actor`, `Audio`, `Player`, `BgCheck`, ...). The table is `config/code.layout.txt`. Functions of source
  files whose name is not known are in `src/code/unknown/` unless all their callers are in one module.
- `src/code/wip/`: unfinished attempts (not tracked by git).
- `asm/code/`: the original assembly (generated by `make split`, not tracked).

New files are written flat in `src/code/`; `python3 tools/srcsort.py` (run by `tools/wave_finish.sh`) files them into
their folder.

## Writing and checking one function

```
tools/mm asm   code func_800BDE3C                          original assembly
tools/mm m2c   code func_800BDE3C                          first draft (often wrong)
tools/mm match code func_800BDE3C src/code/func_800BDE3C.c
tools/mm diff  code func_800BDE3C src/code/func_800BDE3C.c
```

- A function with a registered name (`config/code.names.txt`) is defined under that name; its callees in `code` are
  called by their registered names. Calls into `boot` keep the address name (`func_800XXXXX`): the link of `code`
  does not know the names of `boot`. Run `python3 tools/names.py code --apply-src` before building.
- A match counts only at the exact size of the function. Display-list commands need both writes on one source line,
  and the usual fixes are listed in `tools/AGENT_BRIEF.md` (bit fields, structures of 8 bytes passed by value,
  `-O2 -g0`, unused arguments that the callee receives).
- `tools/mm match` checks one function (a "match" at the wrong size or with extra code is possible). Only
  `make check` proves the segment.

## Working in waves

1. `python3 tools/wave.py code 80 4` writes `build/wave/code.chunkNN` with the smallest functions that have no C yet.
2. Give each chunk to one agent or contributor with `tools/AGENT_BRIEF.md`. Successes go flat to `src/code/`,
   failures to `src/code/wip/`. Nobody runs git during a wave.
3. `bash tools/wave_finish.sh` files the sources, applies the names, verifies both segments and the style, and
   refreshes the numbers. `python3 tools/quarantine.py code` moves back to `wip` what does not hold in the rebuilt
   segment.
4. `make auto HOURS=2` runs the permuter over every unfinished attempt, tidies what it found and verifies it.
5. `make check` must pass before every commit.

## Assembly that stays assembly

The few hand-written functions are marked in the splat output (`Handwritten function`) and are not counted in the C
numbers. The numbers are in [PROGRESS.md](PROGRESS.md).
