# The `boot` segment

`boot` is the first code the console runs: the libultra operating system, the C library, the math library and the
low-level game startup (DMA manager, fault handler, interrupt manager, heap). It is `0x198D0` bytes of the ROM
(`ROM[0x1000:0x1A8D0]`, extracted by `tools/extract.py` to `build/boot.bin`), linked at `0x80080000`, with 479 functions.

## Layout of the sources

- `src/boot/<module>/func_XXXXXXXX.c`: one C file per function, in a folder per source file of the original game.
  The table is `config/boot.layout.txt`; the SDK names go to `libultra/os`, `libultra/io`, `libultra/gu` and
  `libultra/libc`. Functions of source files whose name is not known yet are in `src/boot/unknown/`.
- `src/boot/unknown/`: verified functions whose source file is not known yet. `src/boot/wip/`: unfinished attempts, not matching and not tracked by git (see [CONTRIBUTING.md](CONTRIBUTING.md#where-a-file-goes-module-folder-unknown-or-wip)).
- `asm/boot/`: the original assembly (generated by `make split`, not tracked).

New files are written flat in `src/boot/`; `python3 tools/srcsort.py` (run by `tools/wave_finish.sh`) files them into
their folder.

## Writing and checking one function

```
tools/mm asm   boot func_80086A14                          original assembly
tools/mm m2c   boot func_80086A14                          first draft (often wrong)
tools/mm match boot func_80086A14 src/boot/func_80086A14.c
tools/mm diff  boot func_80086A14 src/boot/func_80086A14.c
```

- A function that has a registered name (`config/boot.names.txt`) is defined under that name; its callees are called
  by their registered names too.
- The libultra and libc files are built with the older compiler IDO 5.3 when the first lines say
  `// COMPILER: ido53`; the other files use IDO 7.1. Flags are given by `// FLAGS: ...` (see
  [CONTRIBUTING.md](CONTRIBUTING.md) and `tools/AGENT_BRIEF.md` for the idioms that decide matches).
- `tools/mm match` checks one function. Only `make check` proves the segment: it compiles every function, rebuilds
  the whole segment from the C and the remaining assembly, and compares it with the ROM byte for byte.

## Assembly that stays assembly

Functions that were hand-written in the original (marked `Handwritten function` in the splat output) or that no C can
express (`cfc1`/`ctc1`, `floor.w`/`ceil.w`, the hand-written `bcopy`) are listed in `config/boot.asm_only.txt` or
marked by the disassembly. They are built from the original assembly and are not counted in the C numbers. A function is
added to that list only with the maintainer's agreement.

## Tools for the hard cases

`tools/rank_wip.py boot` ranks the unfinished attempts by distance to the ROM; `tools/permute_list.py --auto` runs the
permuter on them; `tools/tidy_perm.py boot` rewrites what it found; `tools/quarantine.py boot` moves back to `wip`
any file that does not hold in the rebuilt segment. `make progress` refreshes the numbers.
